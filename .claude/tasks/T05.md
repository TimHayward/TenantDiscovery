# T05: Dependency and workspace hygiene

Read `CONTRACT.md` first. Wave 2, after T01 has merged. Estimated 2 to 3 hours.

## Objective

The dependency declarations across this workspace do not describe what the code actually needs. Correct them, remove what is unused, converge the duplicated stacks, and add the automation that keeps it correct.

## Why

Almost every runtime dependency of the dashboard is declared under `devDependencies`: React, React DOM, wouter, recharts, TanStack Query and the entire Radix set. Five packages sit in `dependencies`. This happens to work because Vite bundles everything, and it will stop working the moment anyone tries to consume the package any other way or prune dev dependencies in a container build. It also makes the manifest actively misleading about what ships to a browser.

## Files you own

- `package.json` (`dependencies` and `devDependencies` blocks only, not `scripts` or `engines`)
- `artifacts/api-server/package.json`
- `artifacts/m365-dashboard/package.json`
- `artifacts/mockup-sandbox/package.json`
- `lib/*/package.json`
- `scripts/package.json`
- `pnpm-lock.yaml`
- `pnpm-workspace.yaml` (the catalogue only)
- `.github/dependabot.yml` (new)
- Any call site that a library migration requires, listed explicitly in your report

## Out of scope

`minimumReleaseAge: 1440` in `pnpm-workspace.yaml` and its comment block. Do not change, reduce or exclude anything from it. Adding entries to `minimumReleaseAgeExclude` requires a human decision and is not part of this task.

## Work

### 1. Dashboard dependency reclassification

Move every runtime dependency from `devDependencies` to `dependencies`. The test is simple: if the symbol appears in an `import` inside `src/`, it is a runtime dependency. Build tooling (Vite, the plugins, TypeScript, the `@types/*` packages) stays in `devDependencies`.

Do this by reading the imports, not by pattern-matching on package names.

### 2. Remove what is unused

- `cookie-parser` and `@types/cookie-parser` in `api-server`. Never imported, never registered. Confirm with grep before removing.
- Any `@types/*` whose runtime package is not present.
- Sweep both applications for other declared-but-unimported packages and list what you find. Be careful: a package can be used without an explicit import (a PostCSS plugin, a Vite plugin referenced by string, a Tailwind plugin). Check the configuration files before concluding a package is unused.

### 3. Converge the duplicated CSV stack

`papaparse` and `react-csv` are both present, with both sets of types. `ExportBtn` already centralises the usage. Read it, determine which library it actually uses, migrate any call site using the other, and remove the loser and its types.

Prefer `papaparse` if the choice is genuinely open: it parses as well as generates, and `react-csv` couples a data concern to a React component.

### 4. Tighten the loose ranges

`express: "^5"` and `cors: "^2"` are major-only ranges, which means any minor or patch within the major satisfies them, and the lockfile is the only thing pinning reality. Tighten both to the current minor.

`thread-stream` is pinned to an exact `3.1.0`. Find out why. It is a pino transport dependency and the pin is probably deliberate, working around an esbuild bundling issue with `esbuild-plugin-pino`. Either document the reason in a comment next to the pin, or, if you can demonstrate the pin is no longer needed by building and running the server, re-range it. Do not remove the pin without demonstrating it.

### 5. Automation

Add `.github/dependabot.yml` covering the npm ecosystem across all workspace packages and the GitHub Actions ecosystem, weekly, grouped so that patch updates arrive as one pull request rather than thirty. Set a sensible `open-pull-requests-limit`.

Note in your report the interaction between Dependabot and `minimumReleaseAge: 1440`: Dependabot will happily propose a package published an hour ago, and `pnpm install` in CI will then refuse it. Say how you would like that handled and leave the decision to a human.

## Verification

Beyond the five gate commands:

1. Delete `node_modules` entirely and run a clean `pnpm install`. Paste the result. A stale `node_modules` will hide a broken manifest.
2. Run `pnpm install --frozen-lockfile` afterwards and confirm it succeeds, which proves the lockfile you committed matches the manifests.
3. Build the api-server Docker image and start the container, to prove that nothing you moved out of `dependencies` was needed at runtime. This is the check that catches the most likely mistake in this task.
4. For each removed package, paste the grep that shows zero references.
5. Confirm the dashboard build output size is unchanged within a reasonable margin, and state the before and after entry chunk sizes.
6. Confirm `minimumReleaseAge` is unchanged and `minimumReleaseAgeExclude` is still empty.
