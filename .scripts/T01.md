## Work

### 1. The eleven errors

Run `pnpm exec eslint . --quiet` to see them in isolation.

- `build.mjs` reports `no-undef` on `console` and `process`. The flat config has no Node globals block covering root-level `.mjs` build scripts. Add one rather than disabling the rule.
- Two `no-irregular-whitespace` hits are almost certainly a non-breaking space pasted into a string or comment. Find the actual character and replace it. Check whether it is inside a user-visible string before you change it, because in a display string it may be deliberate.
- Three `prefer-const`. Note that the two in `exchange.ts` are on `sharedMailboxes` and `roomMailboxes`, which the backlog records as permanently hardcoded to zero. Change them to `const` and leave the wider behaviour alone; that is item 5.8 and not yours.
- Four `no-empty`. An empty catch block is usually a swallowed error. For each one, work out what is being swallowed. If it is genuinely ignorable, add a comment inside the block saying so and why, which satisfies the rule honestly. If it is not, log it through the existing logger. Do not add `// eslint-disable-next-line`.

### 2. The thirty-three warnings

Mostly unused imports and unused locals, plus four `no-explicit-any` in `SecurityTab.tsx` and four `react-hooks/exhaustive-deps`.

- Unused imports: delete them. Before deleting, confirm with grep that the symbol really is unused in the file, because a JSX-only usage can look unused to a careless read.
- Unused locals: delete, or prefix with `_` only where the value is a deliberately discarded destructuring element.
- The four `any` in `SecurityTab.tsx`: these are the last meaningful `any` in the dashboard. Give them real types drawn from the generated `@workspace/api-zod` types rather than inventing shapes.
- The `exhaustive-deps` warnings: these are the ones to be careful with. Each is telling you that a `useMemo` dependency changes on every render. The mechanical fix (adding the dependency) can change behaviour. Read the surrounding component, make the change the warning actually suggests (hoisting the logical expression into its own `useMemo`), and note in your report what you verified by reading.

### 3. Raise the gate

- Root `package.json`: change the lint script to `eslint . --max-warnings 0` so warnings become failures from here on.
- Add an `engines` field to the root `package.json` and to both application packages, pinning `node: ">=22"` and `pnpm: ">=10"`. The README says Node 18, `replit.md` says 24, and nothing enforces either. Update the README's prerequisites line to match what you pin.
- Add `*.db`, `*.db-journal` and `*.db-wal` to `.gitignore`. `METRIC_DB_PATH` defaults inside the tree on some paths, so a metrics database is currently committable, and it holds tenant personal data.
- Add a coverage step to `ci.yml`. `vitest run --coverage` with `@vitest/coverage-v8`, reporting text and lcov, uploaded as a workflow artefact. Do not set a coverage threshold yet; T02 will raise the number substantially and a threshold set today would be set at the wrong level.
